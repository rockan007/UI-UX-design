# 设计原则

## 核心原则

- 界面服务于任务完成，而非装饰。
- 清晰的信息层级优先于视觉效果。
- 主要操作必须显而易见；次要操作必须克制。
- 布局、间距、颜色和组件状态必须保持一致。
- 移动端是真实的体验，不是压缩的桌面端。
- 桌面端优先考虑效率；移动端优先考虑可读性和触控目标。

## 视觉风格

- 页面背景使用中性色。分区区域可使用 `design-tokens.md` 中的浅色调背景令牌（`surface-*`）来在不同内容区域之间形成视觉区分。
- 品牌色用于主要操作、选中状态和关键反馈。语义色（蓝、青、琥珀、绿）可用于数据可视化、统计卡片的强调色条以及色调卡片背景。
- 禁止：渐变背景、霓虹色、饱和背景。允许：微妙的色调背景（`*-50` 级别令牌），仅图表容器可使用 `shadow-sm`。
- 管理后台圆角：6px。前端：8px。
- 阴影：`shadow-sm` 仅用于浮层组件和图表/数据可视化容器。`shadow-md`/`shadow-lg` 用于对话框、抽屉、下拉菜单。表格、表单、列表容器或统计卡片不使用阴影（统计卡片使用强调色条，而非投影）。

## 管理后台容器系统

管理后台页面使用三种容器层级来创建视觉节奏。不要对每个内容块使用单一扁平的卡片样式。

### 容器层级

| 层级 | 样式 | 使用场景 |
| --- | --- | --- |
| **强调卡片** | 白色背景 + `border` + 左侧 3px 彩色条 | 统计/指标卡片 — 颜色根据 `design-tokens.md` 强调色条表区分数据类别 |
| **浮起面板** | 白色背景 + 无边框 + `shadow-sm` | 图表容器、关键数据可视化 — 浮动于页面表面之上 |
| **标准块** | 白色背景 + `border`（当前默认） | 表格、表单、活动列表 — 保持功能区域清晰可扫描 |

### 分区着色

当页面有 3 个或以上独立的内容分区（每个分区都有自己的标题 — 例如：统计行、图表面板、数据表格、活动动态）时，将相关卡片组合在浅色调背景包裹器（`surface-*` 令牌）内，以形成视觉"区域"。每个分区包裹器使用 `rounded-md` 内边距和相应的 `surface-*` 背景。

- "分区"是指具有自己标题的独立内容块 — 统计行、图表面板、数据表格、活动动态、筛选栏 + 结果列表。
- 只有 1-2 个分区的页面保持扁平 — 不需要分区着色。
- 分区背景始终使用 `*-50` 级别的色调令牌。绝不使用饱和或深色背景。

## 前端目标

面向普通用户。优化低理解成本和清晰的操作路径。

**应该做：**
- 立即展示页面目的。
- 让主要的下一步操作可见。
- 清晰地对内容进行分组。
- 保持表单简短，并提供明确的反馈。
- 在移动端保持可读性和触控目标。
- 使用用户友好的错误语言。

**不应该做：**
- 延迟任务的空洞营销视觉。
- 过多的装饰性卡片。
- 隐藏或模糊的主要操作。
- 没有标签的纯图标含义。
- 移除关键操作的移动端布局。

## 管理后台目标

面向高频操作用户。优化效率、稳定性和可扫描性。

**应该做：**
- 保持布局结构稳定。
- 使用中到高的信息密度。
- 使表格、筛选器、批量操作和表单清晰明了。
- 保持状态、时间、金额和数量字段易于扫描。
- 明确确认破坏性操作。

**不应该做：**
- 过大的营销风格标题和留白。
- 过度圆角的控件、厚重的阴影、装饰性渐变。
- 当表格或列表更高效时使用卡片密集型布局。
- 混乱的主/次按钮层级。
- 整个页面使用统一扁平的卡片样式 — 根据容器层级系统变化容器处理方式。

## 移动端列表页

在 768px 以下的视口中，管理后台列表页从表格布局切换为卡片列表布局。桌面端表格布局在 768px 以上保持不变。

- 每个表格行变为一个堆叠卡片，包含 4 层：主 ID + 状态、人员/实体 + 金额、属性标签、元信息 + 操作。
- 搜索输入框保持可见。其他筛选器移入底部抽屉（`el-drawer` direction btt）。
- 分页简化为上一页/下一页按钮和页码指示器（`1 / N`）。
- 统计卡片在移动端使用 `grid-cols-2`，采用紧凑内边距（`p-2.5` 而非 `p-4`）和较小字号（`text-base` 而非 `text-2xl`）。
- 操作按钮移入三点下拉菜单（`el-dropdown` 配合 `MoreFilled` 图标）以节省水平空间。
- 使用 `hidden md:block`/`hidden md:flex` 控制桌面端元素，`md:hidden` 控制移动端元素。不要使用带窗口宽度的 `v-if` — CSS 断点已足够。

## 管理后台 CRUD 导航

- 列表 → 新建：列表页上的"创建"按钮，导航至 `/admin/{entity}/create`。
- 列表 → 详情：点击行/卡片导航至 `/admin/{entity}/:id`。
- 详情 → 编辑：详情页上的"编辑"按钮，导航至 `/admin/{entity}/:id/edit`。
- 新建/编辑/查看共享同一个表单组件，通过路由名称检测模式。查看模式：只读字段，面包屑行显示状态标签，编辑 + 删除工具栏按钮。新建模式：空白可编辑字段，提交 + 取消按钮。编辑模式：预填可编辑字段，保存 + 取消按钮。
- 所有导航反映在面包屑中，跟踪操作路径。
- 表单字段：必填字段归类在"基本信息"下，次要字段归类在"其他信息"下，使用分割线分隔。

## 管理后台 Shell 布局（强制）

所有管理后台页面必须使用共享的 `AdminLayout` 外壳，无论其路由前缀（`{admin-prefix}`）是什么。绝不要构建带有自己侧边栏或页头的独立管理后台页面。

**布局结构：**

```
AdminLayout (el-container, h-screen)
├── AdminHeader (el-header, 48px)
│   ├── 左侧：系统图标 + 系统名称
│   └── 右侧：通知徽章 + 语言下拉菜单 + 用户头像下拉菜单
├── 移动端栏 (md:hidden) — 汉堡按钮打开抽屉
└── el-container (body)
    ├── AdminSidebar (el-aside, 展开 220px / 折叠 64px)
    │   ├── 折叠切换按钮 (☰ 汉堡图标，右上角)
    │   └── el-menu (router 模式, collapse prop)
    │       ├── el-menu-item — 叶子菜单项 (图标 + 标签)
    │       └── el-sub-menu — 带有子项的父级菜单
    └── el-main (bg-neutral-50, 内边距 24px)
        └── router-view — 页面内容
```

**侧边栏菜单规则：**
- 菜单通过 `el-sub-menu` 支持多级嵌套。一级嵌套为标准做法；避免超过 2 级的深层嵌套。
- 叶子项使用 `el-menu-item`，`index` = 路由路径，用于路由导航。
- 父级项使用 `el-sub-menu` 包含子项；父级本身不进行导航。
- 折叠状态：展开（220px，图标 + 标签），折叠（64px，仅图标带 tooltip）。
- 激活项：`bg-brand-50 + text-brand-600 + font-medium`。
- 未激活悬停：`bg-neutral-50`。
- 移动端：完整菜单渲染在 `el-drawer` 内（260px，左侧，无标题）。

**文件位置：**
- `src/layouts/AdminLayout.vue` — 布局外壳
- `src/components/AdminHeader.vue` — 顶栏
- `src/components/AdminSidebar.vue` — 带多级菜单的侧边栏

**创建新的管理后台页面时：**
1. 将路由添加为 `{admin-prefix}` 下的子路由，使用 `AdminLayout` 作为父组件。
2. 将对应的菜单项添加到 `AdminSidebar.vue` 的菜单结构中。
3. 不要在页面组件自身中创建新的布局包裹器、侧边栏或页头。

## 内容指南

### 错误消息

结构：**发生了什么 → 为什么 → 该怎么办**。

| 方面 | 前端 | 管理后台 |
| --- | --- | --- |
| 语气 | 友好、有帮助 | 精确、直接 |
| 技术术语 | 避免使用 | 可在详情中使用 |
| 操作引导 | 明确的下一步操作 | 重试、导出、联系管理员 |
| 示例 | "页面加载失败。请检查您的网络并重试。" | "请求超时 (500)。请重试或联系运维。" |

### 空状态

- 说明缺少什么。
- 告诉用户下一步该做什么。
- 如果用户有权限，提供创建入口。
- 绝不显示空白页面。

### 按钮文案

- 使用动词：保存、删除、取消、搜索、导出。
- 避免模糊的标签：确定、确认、知道了。
- 破坏性按钮必须指明操作："删除用户"、"清除数据"。

## 质量标准

一个好的页面满足以下条件：
1. 用户知道页面的目的。
2. 用户知道下一步该做什么。
3. 关键信息可快速扫描。
4. 页面在错误/空状态下仍然可用。
5. 核心任务在移动端可用。
6. 视觉风格统一、克制且稳定。
