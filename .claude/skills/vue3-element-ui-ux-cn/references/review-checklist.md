# 审查清单

实现后质量审查。每次页面生成后运行此清单。

## 审查提示词

```
以资深 UI/UX 设计师的身份审查此页面。
只指出具体问题，不讨论泛泛之谈。

按严重程度排序：
1. 阻碍任务完成的问题
2. 信息层次问题
3. 视觉一致性问题
4. 表单或表格体验问题
5. 移动端问题
6. 无障碍访问问题

然后修复问题。不要更改业务逻辑。
```

## 1. 任务完成路径

- [ ] 用户知道这是什么页面。
- [ ] 用户知道下一步该做什么。
- [ ] 主要操作显而易见。
- [ ] 次要操作不与主要操作冲突。
- [ ] 破坏性操作有确认步骤。
- [ ] 操作完成有反馈。
- [ ] 用户可以轻松撤销或返回。

## 2. 信息层次

- [ ] 页面标题清晰。
- [ ] 关键数据在次要细节之前展示。
- [ ] 主要信息比次要信息更突出。
- [ ] 帮助/描述文字简洁。
- [ ] 状态信息易于识别。
- [ ] 没有相互竞争的视觉焦点。

## 3. 视觉一致性

- [ ] 按钮样式和尺寸一致。
- [ ] 表单控件高度统一。
- [ ] 表格行高一致。
- [ ] 标签和徽章共享统一的风格。
- [ ] 分区间距稳定。
- [ ] 圆角和阴影使用克制。
- [ ] **连接线与边框圆角：** 单侧有边框连接线的容器，该侧的圆角设为 `0`。使用方向性圆角（`rounded-r-*`、`rounded-l-none`）而非统一的 `rounded-*`。
- [ ] **柱状图间距：** 桌面端柱间距约为柱宽的 50%。柱顶平直（不使用 `rounded-t-*`）。柱宽使用阶梯式固定宽度（`md:w-10 lg:w-12 2xl:w-14`），而非 `flex-1`。
- [ ] **容器多样性：** 包含多个内容分区的管理后台页面使用多样化的容器处理方式（强调卡片、浮起面板、标准块）—— 而非全篇统一的白底卡片。
- [ ] **强调色条：** 统计/指标卡片有 3px 左侧边框色条，颜色根据 `design-tokens.md` 强调色条表格匹配数据类别。
- [ ] **浮起面板：** 图表容器和数据可视化面板使用 `shadow-sm` + 无边框，区别于数据表格。
- [ ] **分区底纹：** 分区包裹器默认不使用底色背景 —— 透明，显示页面背景。`surface-*` 底色为可选项，应克制使用。
- [ ] **阴影限制：** 仅图表/数据可视化容器使用 `shadow-sm`。表格、表单、统计卡片和列表容器不使用阴影。
- [ ] **色调背景克制：** 如果使用分区底色（可选），仅使用 `*-50` 级别的令牌。不使用饱和或深色背景。默认为无底色。
- [ ] **面包屑：** 管理后台页面使用 `el-breadcrumb` 分隔符 `/` 替代 `<h1>` 标题。最后一项为当前页面（不可点击）。前面的项带有 `:to` 链接。反映操作路径，而非侧边栏层级。
- [ ] **CRUD 面包屑：** 新建/编辑/详情页面具有反映操作路径的多级面包屑（如 `订单管理 / ORD-001 / 编辑`）。
- [ ] **表单分组：** 各区块为带有左侧强调色条（`border-l-[3px]`）的独立卡片，通过 `gap-4` 分隔。而非单张卡片内使用分隔线。
- [ ] **详情页：** 头部显示记录 ID + 状态，信息以两列卡片展示，底部有包含编辑/删除的操作栏。
- [ ] **CRUD 导航：** 列表页有"创建"按钮；行/卡片点击导航到表单查看模式；查看模式有编辑/删除操作。创建、查看和编辑共享同一个表单组件。

## 4. 表单体验

- [ ] 字段顺序遵循用户工作流程。
- [ ] 标签清晰。
- [ ] 必填字段已标记。
- [ ] 帮助文字必要且简洁。
- [ ] 错误信息在对应字段附近。
- [ ] 提交反馈明确。
- [ ] 防止重复提交（按钮加载中 + 禁用）。
- [ ] **表单工具栏：** 操作按钮放在与面包屑同行的工具栏中（`justify-between`）。主按钮 `type="primary"`，次要按钮 `plain`。不在表单底部。
- [ ] **区块卡片：** 每个区块为带有左侧强调色条（`border-l-[3px]`）的独立卡片。卡片之间通过 `gap-4` 分隔。不使用单卡片加分隔线的模式。
- [ ] **字段网格：** 桌面端使用 `grid-cols-3`。文本域和动态列表在网格行之后、区块末尾全宽展示。多个网格行使用 `mt-4` 堆叠。
- [ ] **表单宽度：** 不使用 `max-w-2xl` 约束。表单使用可用内容宽度。
- [ ] 移动端输入流畅。
- [ ] **三模式表单：** 表单通过路由名称处理创建/查看/编辑。查看模式：只读展示（`v-if="isView"`），面包屑中有状态标签，工具栏包含编辑+删除。查看模式下无校验规则。
- [ ] **一对多子表单：** 子列表使用多列网格并带有列标题（编辑 + 查看）。每行有输入框/只读文本 + 自动计算小计 + 删除按钮。`addItem` 使用字段默认值。合计 = 小计之和。
- [ ] **标签页表单（适用时）：**
  - [ ] 决策矩阵正确应用：仅当有 3 个以上逻辑分组或 2 个以上一对多/多对多关系时使用标签页
  - [ ] 标签栏位于工具栏和表单内容之间，而非包裹在卡片内
  - [ ] 每个一对多/多对多关系有自己的专属标签页并带有数量徽章
  - [ ] 一对多/多对多标签页使用紫色强调色条（`border-l-purple-600`）+ `text-purple-700` 标题
  - [ ] 标签切换即时响应，切换时不触发校验
  - [ ] 单次提交校验所有标签页；隐藏标签页上的错误会自动切换并将标签页标记为红色
  - [ ] 桌面端：标签栏可见，一次显示一个面板
  - [ ] 移动端（<768px）：标签页折叠为平铺的垂直区块卡片，无标签栏，无下拉菜单
  - [ ] 标签栏无横向滚动；所有标签一次排满

## 5. 表格体验

- [ ] 高频字段左对齐。
- [ ] 操作列：≥2 个按钮时仅显示图标，每个按钮包裹在 tooltip 中，按文本方向左/右对齐（不居中），列宽按最坏情况按钮数计算。
- [ ] 筛选区域紧凑。
- [ ] 状态、时间、金额、数量字段易于浏览。
- [ ] 批量操作清晰。
- [ ] 空状态提供下一步指引。
- [ ] 数据在移动端仍可管理。

## 6. 状态反馈

- [ ] **加载中**：清晰显示，无大幅布局偏移；关键数据区域使用骨架屏。
- [ ] **空状态**：有说明和下一步操作。
- [ ] **错误状态**：具体的错误信息，提供重试或返回操作。
- [ ] **成功反馈**：保存/创建/删除后有反馈，不会阻塞过久。
- [ ] **禁用**：可识别，原因可理解，不只用颜色表示。
- [ ] **权限拒绝**：清晰说明。
- [ ] **悬停**：交互元素显示悬停状态。
- [ ] **聚焦**：键盘焦点可见。

## 7. 响应式

```
在以下宽度检查：
- 1440px：布局良好利用横向空间。
- 1024px：不拥挤，减少复杂列。
- 768px：进一步简化列。
- 390px：单列布局，无横向挤压。
```

- [ ] 无文字溢出。
- [ ] 无元素重叠。
- [ ] 触控目标足够大。
- [ ] 筛选、菜单、对话框可用。
- [ ] 表格有移动端解决方案（卡片列表或横向滚动）。
- [ ] **移动端卡片列表：** 管理后台列表页在 768px 以下从 `el-table` 切换为卡片列表。每张卡片显示 4 层：主 ID + 状态、人员 + 金额、标签、元信息 + 操作。
- [ ] **筛选抽屉：** 移动端搜索输入框可见；其他筛选条件在底部抽屉（`el-drawer` direction btt）中，带有应用/重置按钮。
- [ ] **移动端分页：** 简化的上一页/下一页及页码指示器（`1 / N`），移动端无每页条数选择器和总数显示。
- [ ] **摘要卡片响应式：** `grid-cols-2 md:grid-cols-3`，`p-2.5 md:p-4`，移动端使用紧凑字号（`text-base md:text-2xl`）。
- [ ] **操作菜单：** 卡片操作使用 `el-dropdown` + `MoreFilled` 图标，触发器上使用 `@click.stop`。
- [ ] **仅使用 CSS 断点：** 使用 `hidden md:block`/`md:hidden` 控制可见性 —— 不使用带窗口宽度的 `v-if`。
- [ ] 移动端主要操作可见。
- [ ] **操作按钮位置：** 桌面端新建按钮位于筛选栏行内（通过间隔右对齐）。移动端新建按钮为面包屑行右上角的圆形 `+` 图标（`md:hidden`）。无独立的按钮行。
- [ ] 折叠的侧边栏有 `overflow-x: hidden`，防止溢出内容产生横向滚动条。

## 8. 无障碍访问

- [ ] 文字与背景对比度足够。
- [ ] 键盘焦点可见。
- [ ] 图标按钮有 tooltip 或 aria-label。
- [ ] 输入框有可识别的标签。
- [ ] 错误状态不只通过颜色传达。
- [ ] 移动端触控目标 ≥ 44px。

## 状态补全提示词

```
检查此页面是否完整覆盖：
1. 加载中
2. 空状态
3. 错误状态
4. 成功反馈
5. 禁用
6. 悬停
7. 聚焦
8. 校验错误
9. 权限拒绝
10. 移动端布局

补全任何缺失的状态。不要更改业务逻辑。
```

## 9. 国际化（启用时 — 检查 `package.json` 中的 `"vue3ElementUiUx": { "i18n": true }`）

- [ ] 所有面向用户的文本使用 `$t()` 键 —— 模板中无硬编码的中文/英文字符串。
- [ ] Element Plus 语言环境通过 `el-config-provider` + App.vue 中的 `watch(locale, ...)` 同步。
- [ ] 数字使用 `$n()` 格式化，日期使用 `$d()`，货币使用 `locales/index.ts` 中定义的区域感知格式。
- [ ] 模板中无裸 `toLocaleString()` 或手动的 `¥`/`$` 前缀。
- [ ] `LocaleSwitcher` 组件在头部存在且功能正常（点击切换所有文本 + el 组件 + 格式化）。
- [ ] `LocaleSwitcher` 在移动端（< 768px）折叠为地球图标。
- [ ] 激活语言在切换器中以品牌色 + 中等字重高亮显示。
- [ ] `locale` 持久化到 `localStorage`，页面加载时恢复。
- [ ] `<html lang>` 属性在语言切换时更新。
- [ ] 外边距/内边距使用逻辑 CSS 属性（`ms-*`/`me-*` 而非 `ml-*`/`mr-*`）。
- [ ] 文本对齐使用逻辑属性（`text-start`/`text-end` 而非 `text-left`/`text-right`）。
- [ ] 方向性图标使用 `rtl:rotate-180` 变体。
- [ ] 操作列对齐跟随文本方向（操作列规则已涵盖 —— 验证 RTL 自然翻转）。
