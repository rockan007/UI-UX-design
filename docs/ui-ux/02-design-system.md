# 设计系统标准

本文件定义 UI 生成时必须遵守的视觉和交互标准。Claude Code 应优先修改和复用设计系统，而不是在每个页面写一次性样式。

## 颜色

- 背景以中性色为主
- 文本使用清晰的层级：主文本、次文本、弱提示、禁用文本
- 品牌色只用于主操作、选中态和关键反馈
- 危险操作使用独立警示色
- 成功、警告、错误、信息状态必须可区分
- 不使用大面积高饱和渐变

## 字体

- 页面标题清楚但不过大
- 后台标题保持紧凑
- 正文和表单文字保证可读行高
- 表格文字应适合快速扫描
- 不使用负字距
- 不使用 viewport width 缩放字体

## 间距

- 页面外边距、区块间距、组件内边距必须有统一规则
- 同类页面使用相同布局节奏
- 表单字段之间留出稳定间距
- 表格行高不能过松或过挤
- 移动端优先单列堆叠

## 圆角与阴影

- 后台系统圆角建议控制在 6px 到 8px
- 阴影只用于弹层、下拉、浮层等需要层级的组件
- 页面区块不要全部做成浮动卡片
- 不使用强烈发光、模糊光斑、装饰性背景块

## 按钮

- 每个区域只保留一个最明显的主操作
- 次要操作使用弱化样式
- 危险操作必须有明确视觉区分
- 图标按钮必须有可访问名称
- 移动端按钮点击面积必须足够
- 禁用态不能看起来像可点击

## 表单

- 字段顺序符合用户填写习惯
- label 清楚，帮助文本简短
- 必填项和错误提示明确
- 长表单必须分组
- 错误提示靠近对应字段
- 提交中按钮进入 loading 和 disabled 状态
- 提交成功或失败必须有反馈

## 表格

- 高频字段靠左
- 操作列靠右
- 状态、时间、金额、数量要便于扫描
- 表头和内容对齐稳定
- 支持加载、空数据、错误状态
- 移动端可改为卡片列表或横向滚动

## 状态组件

每个关键页面至少考虑：

- loading
- empty
- error
- success feedback
- disabled
- hover
- focus
- validation error
- permission denied
- mobile layout

## 响应式

- 1440px：充分利用横向空间
- 1024px：避免布局过挤
- 768px：减少复杂分栏
- 390px：单列优先，保留主操作
