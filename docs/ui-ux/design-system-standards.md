# UI/UX 设计系统标准

这份标准用于约束 Claude Code 的 UI 输出，避免它只做表面美化。适用于前台页面和后台管理系统。

## 整体原则

- 界面服务于任务完成，不做无意义装饰
- 信息层级优先于视觉效果
- 后台系统应克制、稳定、适合长期使用
- 前台系统应清晰、直接、让用户知道下一步做什么
- 桌面端优先效率，移动端优先可读性和可操作性

## 视觉风格

- 使用中性色作为主体背景和文字体系
- 品牌色只用于关键操作、选中态和重点信息
- 避免大面积渐变、霓虹色、过度阴影
- 避免全页面都使用同一种颜色的深浅变化
- 圆角保持克制，后台系统建议 6px 到 8px
- 阴影只用于弹层、下拉、悬浮菜单等需要层级区分的区域

## 字体与排版

- 页面标题要明确，但不要过大
- 后台内容区标题应紧凑，避免营销页式大标题
- 正文和表单文字要有足够行高
- 标签、说明、错误提示要明显但不抢占注意力
- 不使用负字距
- 不用视口宽度动态缩放字体

## 间距

- 页面外边距、模块间距、组件内边距要形成稳定规则
- 相同类型页面应使用一致的布局间距
- 表单字段之间要留出足够距离
- 表格和列表要保证行距可扫描
- 移动端减少横向分栏，改为纵向堆叠

## 按钮

- 每个区域只保留一个最明显的主操作
- 次要操作使用弱化样式
- 危险操作必须有明确视觉区分
- 图标按钮需要 hover/focus 状态和可访问名称
- 按钮在移动端要有足够点击面积
- 禁用态必须可识别，且不应看起来像可点击

## 表单

- 字段顺序应符合用户填写习惯
- 必填项和错误提示要清楚
- 长表单应分组
- 输入框、选择器、日期控件等高度应一致
- 提交反馈必须明确
- 校验错误应靠近对应字段

## 表格

- 表头、数据、操作列要清晰分区
- 高频字段优先靠左
- 操作列靠右
- 数字、金额、状态应便于扫描
- 支持空状态、加载状态、错误状态
- 移动端如果表格过宽，应改为卡片列表或横向滚动，并保证操作可用

## 导航

- 当前页面状态必须明确
- 一级导航不应过多
- 后台侧边栏要稳定，避免频繁变化
- 面包屑用于层级较深的页面
- 移动端导航应收起为抽屉或底部导航，视产品类型决定

## 状态反馈

必须覆盖：

- 加载中
- 空数据
- 请求失败
- 保存成功
- 删除确认
- 权限不足
- 表单校验失败
- 网络异常
- 禁用态
- hover 和 focus

## 可访问性

- 文本与背景要有足够对比度
- 输入框必须有可识别 label
- 键盘 focus 状态必须可见
- 图标按钮必须有语义
- 错误信息不能只靠颜色表达
- 点击目标不能过小
