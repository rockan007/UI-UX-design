# Claude Code UI/UX 工作流

这套流程用于让 Claude Code 专注改进前台和后台系统的 UI/UX。核心原则是：不要一次性要求它“做得好看”，而是让它按设计系统、页面、状态、截图检查逐步迭代。

## 使用目标

- 只优化 UI/UX，不改变业务逻辑
- 优先使用项目已有组件、样式系统和技术栈
- 让页面信息层级更清晰
- 让主要操作更容易被发现和完成
- 补齐加载、空状态、错误、禁用、校验等交互状态
- 保证桌面端和移动端都可用

## 推荐执行顺序

1. 读取项目结构
2. 总结现有 UI 风格和组件体系
3. 建立 UI/UX 设计标准
4. 统一基础组件和全局样式
5. 按页面逐个优化
6. 补齐交互状态
7. 做桌面端和移动端截图检查
8. 根据检查结果修复细节

## 第一步：让 Claude Code 理解项目

```text
请先阅读当前项目结构，理解前端技术栈、组件库、样式系统和已有页面。
不要修改代码。

请总结：
1. 使用了什么 UI 框架或 CSS 方案
2. 当前页面的视觉风格
3. 可复用组件在哪里
4. 当前 UI/UX 上明显的问题
5. 后续建议优先优化哪些页面或组件
```

## 第二步：限定工作边界

```text
接下来你只关注 UI/UX 改进，不要改业务逻辑、接口协议、数据库结构和权限规则。

设计目标：
- 简洁、现代、专业
- 信息层级清晰
- 页面留白合理
- 表单易填写
- 按钮主次明确
- 表格适合高频使用
- 移动端不能拥挤
- 加载、空状态、错误状态要完整
- 不要做营销感首页
- 不要使用过度渐变、大圆角、装饰性卡片

请先提出 UI/UX 改进计划，不要立刻写代码。
```

## 第三步：先统一设计系统

```text
请先统一设计系统，只修改全局样式、主题配置和基础组件。

请重点处理：
1. 颜色
2. 字体大小
3. 行高
4. 间距
5. 按钮样式
6. 输入框样式
7. 表格样式
8. 卡片样式
9. 状态标签
10. 页面最大宽度
11. 移动端断点

不要改业务逻辑，不要重写页面结构。
```

## 第四步：按页面逐个优化

```text
请优化这个页面的 UI/UX：/dashboard

重点：
1. 信息层级是否清楚
2. 首屏布局是否合理
3. 主要操作按钮是否明显
4. 次要操作是否不会抢占注意力
5. 筛选区域是否易用
6. 表格是否易扫描
7. 空状态、加载状态、错误状态是否完整
8. 移动端布局是否可用

要求：
- 不改接口
- 不改业务逻辑
- 优先复用现有组件
- 完成后说明具体改了哪些 UI/UX 问题
```

## 第五步：截图检查和修复

```text
请启动项目并检查页面实际效果。

请分别查看：
- 桌面端 1440px
- 平板端 1024px
- 移动端 390px

检查：
1. 是否有文字溢出
2. 是否有元素重叠
3. 按钮是否过小
4. 间距是否一致
5. 移动端是否拥挤
6. 表格是否难读
7. 表单是否容易填写
8. 主要操作是否明确

发现问题后直接修复，并说明修复结果。
```

## 第六步：状态补全

```text
请检查当前页面是否完整覆盖以下 UI 状态：
1. loading
2. empty
3. error
4. success feedback
5. disabled
6. hover
7. focus
8. validation error
9. permission denied
10. mobile layout

缺失的状态请补齐。
不要改变业务逻辑。
```

## 每次任务都建议附加的约束

```text
不要改业务逻辑。
不要重构系统架构。
只优化 UI/UX。
优先使用现有组件和样式系统。
保持页面专业、克制、清晰。
不要添加无意义装饰。
确保桌面端和移动端都可用。
完成后请实际运行并检查页面。
```
