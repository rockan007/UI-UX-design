# 响应式与状态检查清单

这份清单用于确保页面不是只有默认状态好看，而是在真实使用场景下也可用。

## 响应式检查 Prompt

```text
请检查当前页面在以下宽度下的实际显示：
- 1440px
- 1024px
- 768px
- 390px

重点检查：
1. 文字是否溢出
2. 元素是否重叠
3. 按钮是否过小
4. 表格是否可读
5. 表单是否容易填写
6. 弹窗、下拉、筛选是否可用
7. 主操作是否仍然容易发现

发现问题后直接修复。
```

## 必备 UI 状态

每个重要页面都应考虑：

- 默认状态
- 加载状态
- 空数据状态
- 请求失败状态
- 保存成功状态
- 删除确认状态
- 权限不足状态
- 表单校验失败状态
- 禁用状态
- hover 状态
- focus 状态

## 状态补全 Prompt

```text
请检查当前页面是否完整覆盖以下状态：
1. loading
2. empty
3. error
4. success feedback
5. disabled
6. hover
7. focus
8. validation error
9. permission denied
10. mobile layout

如果缺失，请补齐 UI 表现。
不要改变业务逻辑。
```

## Loading

- 不应让页面突然大幅跳动
- 重要数据区应有骨架屏或清楚的加载提示
- 按钮提交中应有 disabled 和 loading 表现
- 重复提交应被阻止

## Empty

- 说明当前没有什么
- 告诉用户下一步可以做什么
- 如果有创建权限，提供创建入口
- 不要只显示空白页面

## Error

- 错误信息要具体
- 提供重试或返回操作
- 不要让用户卡死
- 表单错误要靠近字段

## Success

- 保存、创建、删除后要有反馈
- 反馈不应遮挡主要操作太久
- 成功后页面状态应更新

## Disabled

- 禁用原因应可理解
- 禁用按钮不应像可点击按钮
- 不要只依赖颜色差异

## Mobile

- 单列布局优先
- 重要操作保留在可见区域
- 表格可转为卡片列表
- 弹窗宽度应适配屏幕
- 输入控件要有足够点击面积
